| `glove-continuum-signal` | Subprocess-based runtime substrate for agent collaboration across time. Draft v0.1. | `pnpm add glove-lisp` |

| `glove-js` | **REPL surface for tool use** (JavaScript). Progressive discovery is callable in-REPL under BOTH the short names (`search`/`servers`/`fns`/`describe`) and the native-tool-name aliases (`search_functions`/`list_servers`/`list_functions`/`describe_function`), so a model primed on the tool names lands its call. Hardened to the top A/B arm (97%) — see [`JS-EXPLORATION.md`](https://github.com/porkytheblack/glove/blob/main/benches/scratchpad-bench/JS-EXPLORATION.md). Draft v0.1. | `pnpm add glove-js` |
| `glove-python` | **REPL surface for tool use** (Python). Comprehensions, f-strings, slicing, `def`/`lambda`; dunder attributes blocked. `PySession.create()` + `mountPy(glove, { session })`. See [`PY-EXPLORATION.md`](https://github.com/porkytheblack/glove/blob/main/benches/scratchpad-bench/PY-EXPLORATION.md). Draft v0.1. | `pnpm add glove-python` |
| `glove-vfs` | **One virtual filesystem for a whole agent.** The tree a working environment, a `glove-memory` resource store and the REPLs all share, instead of each keeping a private one — so a file the agent MADE can be FILED and read by a script, with no copy and no export step. `Vfs` is nine methods over bytes and absolute paths (`read`/`write`/`rm`/`mkdir`/`exists`/`stat`/`list`/`files`/`totalSize`), deliberately less than any one consumer wants because it is the most every backend can promise; everything richer is an **optional capability** detected with `hasMeta(fs)` / `hasSearch(fs)`, never required by the base type. Backends: `inMemoryFs()` (default), `hostDirectory(dir, { mode })` (copy-on-write over a real directory — nothing on the host changes until `commit()`), `cachedRemote(store, { prefix })` (object storage; you supply `get`/`put`/`delete`/`list`, so no SDK dep). Layers each return a `Vfs` and compose outside-in: `mountFs([...])` (several backends, one tree, longest-prefix routing), `withAccess(fs, policy)` (path-scoped `write`/`read`/`none`, last-match-wins — enforced on the FILESYSTEM, so one rule binds model verbs, scripts, REPL calls and host handles alike), `withMeta(fs, opts)` (summaries/tags/links/provenance and opt-in search in one hidden sidecar). Bridges: `glove-vfs/fns` → `fsFns(fs)` for the REPLs, `glove-vfs/resources` → `vfsResources(fs, { schema, root })` for `glove-memory`, `glove-vfs/testing` → `runVfsConformance()` for backend authors. `snapshot`/`restore`/`copyTree` unwrap the layer stack first, so a restore rebuilds the metadata rather than silently dropping it. Zero dependencies. Draft v0.1. | `pnpm add glove-vfs` |
| `glove-working-environment` | **Persistent working environment for tool use.** Where scratchpad is a stateless-per-call REPL, this is a place state accumulates: a sandboxed in-memory virtual filesystem (`/inbox`, `/scripts`, `/skills`, `/std`, `/tmp`, `/out`, `/.env`) behind a closed verb surface — `write_file`, `edit_file`, `read_file`, `ls`, `grep`, `describe`, `rm`, `mv`, `cp`, `run_script`, `run_tests`, `checkpoint`, `undo`, `redo`, `history` — plus `view_image(path, prompt, page?)` when the host wires a `vision` model — the only verb that catches a VISUAL defect (table off the page, chart with no bars, overlapping title); it rasterizes PDFs/decks for you and `page` is 1-based, so checking slide 3 is one call. All execution goes through named persistent scripts (`export default async function (args)` — validated at write time, sibling `.d.ts` derived from JSDoc, `ls /scripts` is the capability catalog). Scripts import ONLY injected capabilities: `env:fs`, `env:std`, `env:assert`, registered adapters, and each other — no ambient network/host-fs/process access; external capabilities require host-mounted adapters. Scripts run in **worker threads** (`worker.terminate()` is the only thing that stops a compute-bound script). `/skills` is materialised at startup: worked recipes with the exact import line for every module — guessed imports are the #1 measured failure, and `/skills/imports.md` is the fix. Truncate-with-spillover keeps big data in files; per-file undo/redo, run history and named `checkpoint` forks cover recovery. Host doors: `mount` / `export` / `snapshot` / `fromSnapshot`. `createWorkingEnvironment({ stdlib, limits })` + `mountWorkingEnvironment(glove, { env })` (structural — no glove-core dep). Zero-dependency core; heavy format libs live in adapter packages (`glove-env-*`). **Four routes to expose a capability — pick by shape** (see the Working Environment section below): I/O → `defineAdapter`, stateful builder → `defineBuilder`/`defineBuilders`, pure computation → `definePureModule` (synchronous), a capability rather than a library (MCP server, model, HTTP API) → `defineTools`. Host-side options gate verbs: `vision` adds `view_image`, `onPresent` adds `present` (deliver a file from `/out`), `readOnlyPaths` fences subtrees the agent may read but never edit. Test with `glove-working-environment/testing`: `createAdapterTestEnv(adapter)` gives `{ env, fs, script(), runScript(), audit() }`, and `audit()` fails the build when `types` and the real bindings disagree in either direction. Draft v0.1. | `pnpm add glove-working-environment` |
| `glove-env-fetch` | HTTP requests and VFS downloads/uploads as `env:fetch`, with host domain/origin policy, native DNS/IP protection, cancellation and credential aliases. See HTTP files and scoped secrets below. | `pnpm add glove-env-fetch` |
| `glove-env-secret` | Host-backed keystore as `env:secret`: scoped metadata/references, opt-in reveal/writes, pluggable storage outside VFS snapshots. | `pnpm add glove-env-secret` |
| `glove-env-documents` | **Stdlib adapter: documents** for `glove-working-environment` → `env:documents`. One document spec renders to both PDF (pdf-lib) and DOCX (docx): `{ heading }`, `{ text }`, `{ bullets }`, `{ table }`, `{ image }`, `{ pageBreak }` — wrapping and pagination are automatic. `describe(path)` sniffs the format from the bytes. `pdf.merge/split/extractPages/setMetadata/stamp`; `pdf.extractText` needs the OPTIONAL `pdfjs-dist` peer (glyph→character decoding is a font/CMap problem; a naive scan returns plausible nonsense, so it refuses instead). `docx.extractText` reads the OOXML zip with `node:zlib`, no extra dep. PDFs transliterate non-Latin-1 (standard fonts); emit DOCX for full Unicode. Draft v0.1. | `pnpm add glove-env-documents` |
| `glove-env-spreadsheets` | **Stdlib adapter: spreadsheets** for `glove-working-environment` → `env:spreadsheets` (exceljs). `describe(path)` gives sheets/sizes/headers/one sample row at constant cost. `read` returns records keyed by the header row **as plain JSON** — formulas flattened to their result, rich text to a string, dates to ISO, error cells to `#DIV/0!` — plus `totalRows` for `offset`/`limit` paging. Blank headers become column letters, duplicates get `_2`, so no column is dropped; `append` follows the sheet's header order, not the record's key order. `writeSheets`, `toCsv`/`fromCsv`. `.xlsx` only. Draft v0.1. | `pnpm add glove-env-spreadsheets` |
| `glove-env-images` | **Stdlib adapter: images** for `glove-working-environment` → `env:images` (sharp). Image bytes never enter the context window: `describe(path)` reports format/dimensions/space/alpha/EXIF orientation without decoding pixels, `stats(path)` adds channel spread and dominant colour (answers "is this page blank?"). `resize`/`convert`/`crop`/`rotate`/`composite`/`thumbnail`/`contactSheet`, plus `text(input, output, {...})` to draw a caption or watermark. **Animated GIF/WebP survive** `resize`/`convert`/`crop`/`thumbnail`/`composite` — the decision is made against the OUTPUT format, so `.gif`/`.webp` preserve every frame and everything else takes frame one; `rotate` REFUSES an animated source (libvips cannot rotate frames in place — 180° reverses the animation) and names `{ animated: false }` as the opt-out. SVG rasterises with `scale`/`density`; `.svg` output is refused. The output extension picks the encoder unless `{ format }` overrides. EXIF orientation is surfaced rather than silently applied — `rotate(in, out)` with no angle normalises it. Draft v0.1. | `pnpm add glove-env-images` |
| `glove-env-slides` | **Stdlib adapter: slides** for `glove-working-environment` → `env:slides` (pptxgenjs). `create(spec, output)` is the one-call route — layout and sizing automatic. For full control, pptxgenjs's own builder API is exposed **unchanged** via `defineBuilder` — `new Pptx()`, `addSlide()`, `addText()`, chained calls and node refs-in-args all work across the worker boundary. `.pptx` only. Draft v0.1. | `pnpm add glove-env-slides` |
| `glove-env-zip` | **Stdlib adapter: archives** for `glove-working-environment` → `env:archives`. Zip, tar and tar.gz both directions, with **no dependencies** — `node:zlib` and the container formats themselves. `describe(path)` / `list(path)` report entries and sizes without inflating; `extract(path, dir, { include? })` and `create(dir, output, { glob?, format? })`. Inflation is checked against the environment's byte budget before it runs, so an archive that cannot fit is refused rather than discovered. Draft v0.1. | `pnpm add glove-env-zip` |
| `glove-env-media` | **Stdlib adapter: media** for `glove-working-environment` → `env:media` (ffmpeg/ffprobe, bundled via `@ffmpeg-installer` / `@ffprobe-installer`). Audio and video without the bytes entering context: `describe(path)` reports container/streams/duration/bitrate from ffprobe; then `thumbnail`, `frames(input, dir, { fps?, limit? })`, `clip`, `concat`, `transcode`, `extractAudio`, `slideshow`. Also `loudness` (integrated LUFS/true peak/range), `normalize` (two-pass loudnorm, video copied), `waveform`, `extractSubtitles` (`.srt`/`.vtt`/`.ass`/`.ssa`, converting as it goes) and `burnSubtitles` (libass, from an embedded track or a file in the tree); `extractAudio` takes `codec`/`bitrate`/`sampleRate`/`channels`, and `describe` reports `track`/`language`/`title` per stream. Draft v0.1. | `pnpm add glove-env-media` |
| `glove-env-render` | **Stdlib adapter: rendering** for `glove-working-environment` → `env:render`. Rasterizes a document to page PNGs so an agent can LOOK at what it produced: `render(input, outDir, { pages?, scale?, maxWidth? })` → `{ pages, format, totalPages }`. PDFs and images need nothing (pdfjs-dist on @napi-rs/canvas); `.docx`/`.xlsx` need headless LibreOffice, while a `.pptx` falls back to a **layout schematic** drawn from its own OOXML geometry (real frames and text, no theme/fonts/charts — result carries `approximate: true`, good for off-slide/overlap/empty, not for judging looks) — and `libreoffice-core` ALONE IS NOT ENOUGH: it ships no import filters and fails every conversion while exiting 0, which the adapter detects and names. Format decided by magic bytes then extension, so a PDF named .pptx never reaches LibreOffice. Long edge capped at 1600px (a vision model charges by pixels). Pairs with the `view_image` verb. Draft v0.1. | `pnpm add glove-env-render` |
| `glove-env-motion` | **Stdlib adapter: motion** for `glove-working-environment` → `env:motion`. The agent writes a React component; `render(scene, out, opts)` produces an `.mp4`/`.webm`/`.gif`/PNG frames and `still(scene, out, { frame })` a single PNG — so the same capability covers a video, a title card and a chart image. **Time is replaced, not measured**: `requestAnimationFrame` becomes a queue only the renderer drains and `performance.now()`/`Date.now()` return values it sets, so two runs of a 60-frame scene are byte-identical. Scenes are `useFrame()` (pure function of the frame, via the injected `glove/motion` runtime) or **React Native Reanimated, unchanged** — both signals advance every frame and each is inert for the other kind, so there is no mode to pick. React, the Babel/worklets toolchain and ffmpeg SHIP WITH THE PACKAGE; the host supplies only a browser (Chrome/Edge/Chromium found automatically on mac/Windows/Linux), and Reanimated needs the optional `react-native-reanimated` + `react-native-web` peers. **Pass `limits: MOTION_LIMITS`** — a render is refused up front if `runTimeoutMs` cannot cover it, naming the exact fix. `doctor()` / the `glove-motion-doctor` bin / `capabilities()` / the generated `/std/motion/README.md` all answer "can this host render" with per-row fix commands. Draft v0.1. | `pnpm add glove-env-motion` |

**Choose the surface by application shape.** Use `glove-react` + `glove-next` for a focused conversational web interface, `glove-core` for a single headless agent, and `glove-foundry` for a complete agent application with file routing, runtime instances, inbound/outbound integrations, automation, multi-agent work, and inspection. For third-party tools via the Model Context Protocol, see [MCP Integration](mcp.md).

### What's in the framework

- **`glove-core`** — agent loop, tools, display stack, store/model/subscriber adapters, context compaction, inbox, hooks/skills/subagents, `MemoryStore` default in-memory `StoreAdapter`.
- **`glove-react`** — colocated renderers via `defineTool`, `<Render>`, `useGlove`, `MemoryStore`, `createRemoteStore`, `createEndpointModel`, `createRemoteModel`.
- **`glove-next`** — `createChatHandler` (one-line SSE route), voice token handler.
- **`glove-foundry`** — preferred Effect-native application framework and runtime for file-routed, typed, observable agent systems. See the dedicated `glove-foundry` skill.
- **`glove-sqlite`** — deprecated; `SqliteStore` for persistence (server-side only).
- **`glove-voice`** — full-duplex voice pipeline: STT/TTS/VAD adapters, `GloveVoice`, `useGloveVoice`, `useGlovePTT`, `<VoicePTTButton>`.
- **`glove-voice-s2s`** — compatibility runtime for existing avatar, LiveKit and Foundry voiceCall integrations; new realtime agents use `glove-realtime`. Run a Glove agent on OpenAI Realtime, Gemini Live, or GPT-Live: `RealtimeAgent` derives its adapter from `s2sDrivenModel`; `createS2SAdapter` resolves args and `S2S_*` env fallbacks. GPT-Live uses `provider: "openai-live"` with server PCM transport and Responses delegation. Its transcripts are continuous and playback boundaries are host-owned; do not apply Realtime VAD, truncation, or final-turn assumptions to it. See "Speech-to-Speech, Avatars & LiveKit" and [api-reference.md](api-reference.md#glove-voice-s2s).
- **`glove-realtime`** — default for new realtime voice or multimodal agents; independent of `glove-voice-s2s`, whose adapters are not interchangeable. The whole agent on a realtime multimodal model (OpenAI Realtime, Gemini Live, GPT-Live). Adapters own tool registration, synthetic prompts, compaction and modalities, with declared `capabilities` and a standard `RealtimeEvent` stream. `RealtimeSession` runs tools through the Executor, enforces `requiresPermission`, writes the call to the store, injects runtime context and the inbox, bridges subscribers, and handles reconnect, resumption, `goAway` and compaction. `realtimeModel` / `createRealtimeAdapter`; Goals register their own preparation with `useGoalRunner`; use `delivery: "history"` for saved snapshots. `beforeTurn` adds other host preparation. Runnable sales demo: `packages/glove-realtime/examples/live-goals`. See [api-reference.md](api-reference.md#glove-realtime).
- **`glove-voice-avatar`** — live avatars as a rendering layer over the S2S stack: `AvatarAdapter` contract (connect → `view` clients attach to; `sendAudio`/`endUtterance`/`interrupt`, conformance-enforced) + `runAvatarConformance`, `TavusEchoAdapter` (echo PAL, Daily room, `sendInteraction` courier — interactions are data-channel-only), `AnamPassthroughAdapter` (audio-passthrough persona, browser SDK owns audio input → `sendCommand` courier; Anam's plan cap force-ends sessions every few minutes below Growth tier — renew via `disconnect()`+`connect()`), `attachAvatar(rt, avatar)` one-call bridge.
- **`glove-voice-livekit`** — LiveKit as an adapter: `LiveKitTransport` (join room, publish paced agent audio track, remote mics out as PCM events, JSON data channel, `clear()` = server-authoritative barge-in flush) + `attachRealtime(rt, transport)`; LiveKit avatars `TavusLiveKitAvatar`/`AnamLiveKitAvatar` implement the same `AvatarAdapter` contract — the provider's worker joins YOUR room (token kind `agent`, `lk.publish_on_behalf`) and is driven over the `lk.audio_stream` byte stream + `lk.clear_buffer` RPC; token minting via `mintParticipantToken`/`mintAvatarToken`.
- **`glove-mcp`** — MCP servers as first-class tools: `mountMcp`, `connectMcp`, `bridgeMcpTool`, `McpAdapter` (consumer-supplied per-conversation seam). `discovermcp` discovery subagent (registered via `glove.defineSubAgent(discoverySubAgent({...}))`). Opt-in OAuth helpers at `glove-mcp/oauth` (`runMcpOAuth`, `FsOAuthStore`, `MemoryOAuthStore`, `McpOAuthProvider`).
- **`glove-memory`** — Memory layer with five sibling subsystems (entity graph / episodic timeline / resource filesystem / ambient context / forms) and matching `useMemoryReader` / `useMemoryCurator`, `useEpisodicReader` / `useEpisodicCurator`, `useResourcesReader` / `useResourcesCurator`, `useContext`, and `useFormRunner` / `useFormReader` helper families. Storage-agnostic adapter contracts plus reference `InMemory*` adapters for dev/test.
- **`glove-image`** — Agentic image generation. `mountImage(glove, { adapter, assets, library, pipeline?, model?, review?, usage?, onUsage?, curate?, candidates?, requirePermission? })` folds `glove_image_generate` / `_edit` / `_regenerate` / `_import` / `_describe` / `_asset_list` / `_assemble` / `_usage` plus `_character_*` / `_scene_*` CRUD. The prompt pipeline (`expandCharacters`, `expandScenes`, `styleDirective`, `negativeDefaults`, `llmEnhance`, terminal `fitToModel`) turns an intent into the final request with a per-stage trace. Reference adapter: `openrouterImages()` from `glove-image/openrouter`.
- **`glove-classifier`** — Structured-decision (classifier) models behind a `ClassifierAdapter` contract: state + typed questions (`noul` yes/no probability, `choice` label + probabilities + confidence, `score` rubric level + probabilities + confidence) in, typed answers out. `jev()` / `typesafe()` call TypeSafe System One (`TYPESAFE_API_KEY`, `jev-latest`, retries 408/429/5xx); open models on the same `/v1/systemone` API have presets: `kev()` / `laya()` / `von()` / `rizzo()` / `decider()`, each reading `<NAME>_BASE_URL` / `<NAME>_API_KEY`; `systemOne({ baseURL, model, apiKey? })` covers any compatible server; `huggingfaceZeroShot()` / `gliclass()` / `labelScorer({ name, score })` wrap zero-shot "text + labels → scores" models; `llmClassifier({ model })` makes any `ModelAdapter` answer the same questions; `cascade({ primary, fallback, threshold })` re-asks only low-confidence answers; `classifierTool({ classifier })` folds an open `glove_classify` tool and `defineClassifierTool({ name, description, classifier, questions, input?, state?, format? })` a fixed-question one; `gate(answer, { act, review })` → `"act" | "review" | "escalate"`. `mountClassifier(glove, { classifier, classifiers?, presets?, sources?, prefix? })` folds `glove_classify` / `_batch` / `_source` (host data the agent classifies without reading — only ids/labels/answers return) / `_catalog`, and returns `{ addPreset, addSource, removePreset, removeSource, usage }`. `where: { question, choice?, min?, max? }` filters batch/source results. In code: `session.registerAll(classifierFns(clf))` → `classifier.classify/many/is/pick/rate` in glove-js/python/lisp (`many` runs a batch in parallel in one call); `classifierEnv(clf)` from `glove-classifier/env` → `env:classifier`; `withClassifier(browserAdapter, { classifier })` adds `browser.judge({ sessionId, questions })`; `classifierPredicate()` / `classifyInbound()` from `glove-classifier/foundry` triage Foundry inbound transmissions. Jev is not a chat model — never put it behind `createAdapter`.
- **`glove-mesh`** — Inter-agent messaging on top of the inbox primitive: `mountMesh(glove, { adapter, identity })` registers an agent and folds `glove_mesh_send_message` / `_broadcast` / `_list_agents` / `_acknowledge`. `MeshAdapter` is the consumer-supplied transport (BYO); ships `InMemoryMeshAdapter` + `MeshNetwork` for in-process dev/test. Each agent keeps its own inbox; incoming messages land as resolved `InboxItem`s so the existing inbox-injection path surfaces them on the next `ask()`. No authentication — sender ids are unverified.
- **`glove-continuum-signal`** — Subprocess-based runtime substrate modeled on `station-signal` but agent-shaped. `agent("name").input(zod).triggered()|.concurrent()` builder produces branded agents; `ContinuumRunner` discovers them from a directory, pre-warms concurrent ones, dispatches triggered runs from an adapter queue (per-spawn isolation), and routes `notify` IPC envelopes to warm subprocesses inline. `ContinuumAdapter` is the persistence contract (`MemoryAdapter` ships; consumers BYO for SQLite/Postgres/etc.). Single fat `onAgentEvent(envelope)` subscriber forwards every Glove `SubscriberEvent` from any child upstream with the agent identity attached. Mesh integrates by being mounted per-agent inside the factory — no special IPC machinery.
- **`glove-scratchpad`** — Database emulator for LLM tool use. Instead of loading many tool definitions, expose capabilities as a relational database queried with one `execute_sql` tool. Resources (`github_pr`, `emails`, `time`, `images`, …) become tables; CRUD verbs map to (possibly different) underlying tools. `Database.create()`, `defineResource({ name, schema, keys?, volatility, select?, insert?, update?, delete? })` (Zod-first — the schema is columns AND the end-to-end row type) or `resourceFromTool(tool, { name, volatility, schema })`, `mountDatabase(glove, { db })` folds `execute_sql` + `explain_sql` and primes the prompt. Discovery via `information_schema`; `WHERE` equalities push down as arguments (Steampipe's required-key model); writes stage inside `BEGIN … COMMIT` for preview; `EXPLAIN` reports which tools a query hits with no resolver calls. Every statement is parsed and security-gated before any tool runs. MCP servers become tables via `glove-scratchpad/mcp` (`mcpResources` / `mountMcpDatabase`). Backend is `glove-sql` (bundled, zero-dep) or `PgliteBackend` (`glove-scratchpad/pglite`).
- **`glove-vfs`** — The shared tree. One `Vfs` contract with three backends (`inMemoryFs`, `hostDirectory`, `cachedRemote`), a `mountFs` table that composes them into a single namespace, `withAccess` for path-scoped read/write/none enforced at the filesystem, and `withMeta` for summaries, tags, links, provenance and opt-in search. `fsFns(fs)` hands it to the REPLs and `vfsResources(fs, {...})` hands the same tree to a `glove-memory` resource store, so the three sandbox surfaces stop each owning a private filesystem. Zero dependencies.
- **`glove-working-environment`** — A persistent filesystem + script runtime the model writes code against, instead of a fixed menu of tools. `createWorkingEnvironment({ stdlib, limits })` + `mountWorkingEnvironment(glove, { env })`. Scripts run in worker threads and can import only what the host injects. Libraries reach scripts by one of four routes chosen by shape — `defineAdapter` (I/O), `defineBuilder`/`defineBuilders` (stateful builder APIs, unchanged), `definePureModule` (synchronous pure computation), and `defineTools` (a capability rather than a library: an MCP server, a Glove tool, a plain async function). Format adapters ship separately as `glove-env-*`. See the Working Environment section.
